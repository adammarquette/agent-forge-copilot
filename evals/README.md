# Eval golden set + gate (Week 2 HARD GATE)

The Week 2 eval-driven CI gate. Reproducible from this repo alone (no database, no live API) — the golden
cases pin the model's response, so the gate is **deterministic**: a regression anywhere in the extraction
pipeline flips a case and fails the build (Week 2 Core Req 6).

## Layout
- `golden/*.json` — one case per file. Each pins a `stub_model_response`, the expected outcome, and the
  boolean rubrics that apply.
- `baseline.json` — per-category baseline pass rates + the gate policy (`pass_threshold`, `max_regression`).
- `results.json` — generated by a run (git-ignored).

## Rubrics (boolean, not 1–10)
`schema_valid` · `citation_present` · `factually_consistent` · `safe_refusal` · `no_phi_in_logs`.
Extraction rubrics are checked **deterministically** (schema deserialization, substring/log inspection) —
no LLM judge, so the gate cannot drift. `factually_consistent` / `safe_refusal` gain an LLM judge for the
answer-composition cases once P2 (RAG + graph) lands; the judge config will live here.

## Running
```
dotnet run --project tests/GauntletAI.AgentForge.Evals -- evals
```
Exit code 0 = gate passed; 1 = a category is below `pass_threshold` or regressed more than `max_regression`
from its baseline (the build fails). Wired into CI as the `evals` job.

## Coverage
Seeded with the extraction slice (P1): valid lab/intake, schema-gate rejections, non-JSON refusal, and
empty/boundary inputs. Scales toward the 50-case target as retrieval, citation-in-answer, and
missing-data cases are added with P2.
